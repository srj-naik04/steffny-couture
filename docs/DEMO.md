# Steffny Couture — Demo Guide

How to run a clean client demo of the app. Target: a confident walkthrough in
**under 4 minutes**.

---

## 1. Before the demo

1. **Reseed the data** so the shop looks lived-in (15 bookings across every
   status, realistic British names, prices and notes):

   ```sh
   SEED_DATABASE_URL="postgresql://postgres.<ref>:<db-password>@<pooler-host>:5432/postgres" \
     node scripts/seed.mjs
   ```

   The script wipes the `bookings` table and rebuilds it — safe to re-run
   between demos. History and notifications are regenerated by the triggers.

2. **Start the app:**

   ```sh
   npx expo start
   ```

   Press `i` for the iOS simulator, or scan the QR code with Expo Go on a
   physical iPhone.

3. **Have two devices ready** if showing the live customer ↔ shop loop — one
   in customer view, one signed in as the shop.

4. **Shop login:** `steffi@steffnycouture.co.uk` · password shared separately.

---

## 2. The 4-minute script

| # | Step | What it shows |
|---|------|---------------|
| 1 | On the customer device, tap **Book an alteration** and complete the wizard — pick *Hem*, add a photo, describe the change, choose a slot, enter contact details, confirm. | The 90-second booking flow, photo upload, validation, the confirmed screen. |
| 2 | Point out the booking reference (`SC-xxxxxx`) and the success screen CTAs. | Reference generation, WhatsApp / add-to-calendar actions. |
| 3 | Switch to the shop device — the new booking is already on **Today** under "Needs a quote". Open it. | Real-time dashboard, the KPI strip. |
| 4 | Set a **price quote**, then tap **Confirm booking** → **Start work** → **Mark ready**. | Status workflow, the audit timeline, save-on-blur pricing. |
| 5 | Back on the customer device, open **My bookings → the booking**. The status and timeline have updated; the notification bell shows a badge. | Live status, the in-app notification centre. |
| 6 | On the shop device, show **Bookings → Kanban** (drag a card between columns), **Calendar** (tap a day), and **Customers**. | The kanban board, calendar overview, customer history. |

Reset between runs with the seed command in step 1.

---

## 3. Distribution

- **Quick path — Expo Go:** run `npx expo start` and share the `exp://` link;
  the client installs Expo Go from the App Store and opens the link.
- **Polished path — TestFlight:** `eas build --profile preview --platform ios`
  then `eas submit` / an internal-distribution invite to the client's Apple ID.
  `eas.json` carries the `preview` and `production` profiles.

---

## 4. Known limitations (demo honesty)

- **Push notifications** need a development/EAS build — Expo Go no longer
  issues push tokens. The **in-app notification centre** works everywhere and
  is the thing to show.
- **Emails** don't send yet — the `send-email` Edge Function and templates are
  written but not deployed (needs a Supabase access token + SMTP credentials).
  Booking/notification data is all live regardless.
- **Branded app icon / splash** — `app.json` is configured; the final artwork
  is generated from `assets/branding/*.svg` (see that folder's note).
